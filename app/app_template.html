No globals

        
Open every sample in one swmm5-rust instance

        
Each model gets its own handle, a Box<Project> that owns everything the model needs. They are stepped in turn, one routing step each, inside a single WebAssembly instance. Then each result is checked against a solo EPA run of the same model.

        

        

      

      
Why this works. EPA SWMM 5.2.4 keeps its working state in process-wide variables, so a program holds one model at a time. In swmm5-rust there are no globals for a second model to overwrite: every value lives in a Project, and every function takes the one it works on as its first argument.

About swmm5-rust

        
swmm5-rust is EPA SWMM 5.2.4 translated into safe Rust. The engine crate forbids unsafe code, so the compiler checks every array index and every reference, and nothing it computes differs from EPA's engine: the binary output and the report match byte for byte wherever EPA's own behaviour is defined.

        
This page runs three engines compiled to WebAssembly: EPA SWMM 5.2.4 from the official v5.2.4 tag, swmm5-cplus (the same engine restructured in C++), and swmm5-rust.

        
The EPA Storm Water Management Model is a work of the U.S. Environmental Protection Agency, in the public domain. Version 5.2.4's engine is Lewis Rossman's design; both translations keep every algorithm as he wrote it.

AI use

        
swmm5-rust, this app and its Doc essay were built with Claude, Anthropic's AI model (Claude Opus 5.5), in one session on 28 and 29 October 2026, at the request of Robert (Bob) Dickinson, who chose the goal (safe Rust, byte-identical to EPA 5.2.4) and supplies the model corpus it was tested on. Responsibility for publishing the work is his.

        
What Claude did: ran c2rust on EPA's source and wrote the passes that made its output build on stable Rust and convert floats as x86 does; wrote the safe engine's skeleton and the translation rule book; ran the translation of the 54 modules as ten batches of parallel agents and integrated them; wrote ccast, cio and their tests against glibc; found and fixed the FILLED_CIRCULAR drift; wrote the C interface, the WebAssembly build, the in-memory file system the engines run on here, the gates, the lockstep tool, this page, its figures and the essay.

        
How it was checked: mechanically, not by the AI's judgment. Byte comparison of every .out and .rpt against EPA 5.2.4 built from the official tag, natively and in WebAssembly; a platform control; the glibc comparisons. Not yet checked by a person: the translation has not been reviewed line by line by Bob, and the gates have not been rerun on his machine.
